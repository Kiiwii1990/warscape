## Shared loot support

Native `LootStoreItem` counts are uint8. This release does not widen TrinityCore's
loot fields, change its schema, clamp drops to 255 or alter the existing Coins
stack size. Fixed quantities above 255 use a native reference template (970000)
containing 200 Coins. Outcome rows repeat that reference and optionally add the
remainder: 450 is 2*200+50, 460 is 2*200+60, and 3000 is 15*200. Both native
reference-rate settings were verified as 1 before deployment; changing referenced
amount scaling would change these quantities and requires a reviewed update.

The compiler validates fixed counts, 200-stack reference contracts, reference-ID
collisions and the native 18-slot normal-loot budget. A 3000-Coin roll plus one
bone/ash consumes 16 slots. Variable large ranges are refused, not rounded.
Preconditions require absent reference IDs and the existing item stack size;
postconditions verify the reference and every outcome row/repetition/remainder.
The existing native reference loader/processors handle runtime generation. Prior
release SQL/specifications still reproduce unchanged.

`rare_table` models the ordinary RDT, its embedded gem table and its direct
mega-rare branch using exact fractions. The pre-Legends gem branch converts its
mega slot to the configured talisman. The RDT's direct mega branch is not quest
gated, matching the reviewed source distinction: Rune spear/Shield left half/
Dragon spear remain possible there. No Ring of Wealth is assumed. Regular entries
use the existing surface Nature talisman policy; explicitly cave-only source
tables use Chaos talisman. This is per-variant configuration, not a live custom
world geography/quest evaluator. All old gem-helper calls retain their default.

Members-style ordinary main loot applies to all accounts. Quest/Slayer/Wilderness
tertiary, clues, ensouled heads and special conditional drops are still deferred.
Collectibles retain their existing non-functional policy: no equipment bonuses,
currency, Prayer, food, crafting, farming or opening/combining mechanics. Noted
quantities use the same stackable collectible item, without note conversion.

## Source policies and limits

- Ice giants include seven level-53 source appearances and three level-67 cave
  appearances with separate main tables. The listed cave main probabilities total
  61/62; the unlisted 1/62 is explicitly empty. This is an authoring assumption,
  preserving every listed chance. The uncommon-seed source's separate 2/1048 gap
  retains the previously documented empty-slot policy.
- Moss giants include three source level/location variants. Fire giant includes
  only the zero-bonus level-86 version. Both drop Big bones. Hill giant's special
  key/location table and higher Fire giant XP bonuses are separate work, so this
  checkpoint does not advertise complete coverage of every Giant variant.
- Lesser/Greater demons drop one Vile ashes; Black demons drop one Malicious ashes.
  Chasm of Fire preferred-method double ashes are conditional and not granted
  unconditionally. Regular/cave tables and source stats remain distinct; no
  Wilderness/Slayer tertiary or Chasm task mechanics are introduced.
- Werewolves spawn already transformed. Twenty named Canifis source identities
  and two GWD variants have their own source IDs/profiles; some use the same WoW
  model/stats. They drop Wolf bones plus the ordinary main roll. Human disguises,
  transformation, Wolfbane, merchant/quest interactions and faction-item protection
  are not implemented. Source Canifis respawn is N/A; the registry uses a 35-tick
  placeholder metadata value, not a live respawn rule. GWD retains 25 ticks.
- Mountain trolls preserve published zero Ranged and Magic stats. Previously the
  loader/scaler required every stat to be at least one. `MinimumMonsterStat` now
  permits zero only in monster Ranged/Magic; melee and Hitpoints minima remain one.
  Profile inheritance still uses zero overrides to mean inherit. Player skill
  levels, XP curves and persistence are untouched. Before migration, a read-only
  check confirmed no existing profile had zero Magic/Ranged; accepting these
  values therefore enables only the two new Troll profiles in this database.
- Mammoth keeps Big bones and its seed/herb/main/RDT distributions. The rare
  3000-Coin outcome uses native references. Conditional Wilderness/task bonuses
  and tertiary drops remain out of scope.
- Magic axe and Possessed pickaxe each have regular and Catacombs variants; Animated
  spade adds one source form. Regular versions drop Iron battleaxe/Iron pickaxe/
  Spade. Catacombs versions use 475/10/10/4/1 weights out of 500 for iron/steel/
  mithril/adamant/rune tools. All remain ordinary melee prototypes without original
  dungeon/event mechanics. Missing tool Slayer XP is HP reference metadata only.

fire-skinned Ogre. These are stock silhouette/colour stand-ins. Demons use horned
Felguard models scaled by Lesser/Greater/Black tiers, without custom dark skins.
Werewolves use classic Duskwood worgen; Trolls use tribal/forest troll stand-ins;
Mammoth uses the stock wooly model. These follow the supplied family directions,
but exact OSRS proportions, sounds and colours require manual acceptance.

Animated tools use Kael's native Devastation display 26081, which resolves to an
InvisibleStalker rig, plus visible hand equipment: actual Devastation item 30316,
Mining Pick 2901 or Farmer's Shovel 3334. The creature display ID is not the item
ID. Native stock weapon NPC 21269 uses this rig with a separate virtual item;
no Kael encounter AI, event item abilities or raid spells are copied. The model
and hand-item audits pass; floating appearance, targeting, attack animation and
attachments remain explicit in-game checks. A model audit alone cannot prove the
visible weapon presentation.

21 native equipment rows configure giants, Trolls and animated tools; actual count
is recorded after verification below. Existing equipment rows are untouched.
97 new collectibles (902175-902271) use stock artwork and preserve every prior
client/server Item.dbc row/string and unrelated locale-patch payload. No client
executable, object field, allocation/lifetime or memory-layout code changes occur.
