# Warscape automated melee attack test

This is a GM development utility using the existing Warscape Training Dummy.
It changes no combat formulas, bonuses, damage scaling, attack scheduling or XP
rules, and introduces no gameplay stage or database migration.

## Commands

Use a GM character with NPC-add permission. Spawn a dummy using `.rs dummy` (or
use a saved dummy), select it, equip the desired weapon and choose a style.

```text
.rs attacktest 5
.rs attacktest status
.rs attacktest stop
.rs attacktest cancel
```

The duration must be a whole number of minutes from 1 through 30. Start requires
a selected, living Warscape Training Dummy and a living player outside a vehicle
who can attack it. It starts normal server melee auto-attacks, including the
usual client attack-start message. An already-running attack on that dummy is
left on its current timer. Overlapping test sessions are refused.

There is no movement automation. If you start out of range, face away, lose line
of sight, become unable to attack, cast, or stop auto-attacking manually, time
continues and the interruption is tracked. Return to a valid position or resume
auto-attacking normally; no extra swings are generated by the collector.

`status` reports remaining time and recorded swings. `stop` stops the test early
and prints results. `cancel` stops it and discards results, with only an
acknowledgement. These commands do not require keeping the dummy selected after
the test starts. Automatic completion stops attacking before another scheduled
player update can swing. The deadline is checked each player update; report
duration/DPS use the actual monotonic elapsed time, including update latency.

## What is measured

The collector observes `Unit::AttackerStateUpdate` after normal melee damage
calculation/mitigation, at the same point the combat packet is sent. It observes
only this player's real main-hand melee auto-attacks against the test's saved
dummy GUID. Each event records a monotonic millisecond timestamp, native hit
outcome and the sum of the displayed damage channels. It never rolls an attack
or changes a timer. Real main-hand extra attacks are included, even if several
occur at the same timestamp. Spell, ranged, pet and proc-spell damage, and queued
abilities replacing an auto-attack, are outside this auto-attack report.

- Hits include successful zero-damage rolls; the report shows their count.
  Average hit and min/max include these zero hits. Misses include the native
  failed/avoided outcomes. Accuracy is hits divided by recorded swings.
- Total damage sums actual recorded damage. DPS divides by actual elapsed test
  time, including interruptions and initial waiting time. No damage is inferred
  from an expected attack rate.
- Average interval is the mean gap between successive recorded timestamps,
  including misses, zero hits and gaps caused by interruptions. Fewer than two
  swings is reported as `n/a`. Expected interval comes from Stage 1F ticks.
- A pause is a continuous observed period of range/facing/LOS/control/auto-stop
  or invalid-target blockage. Its elapsed time and observed reasons are sampled
  on player updates, rather than estimated from missing hits.
- Weapon, style, selected accuracy/Strength bonuses, interval and dummy Defence
  changes mark the result `MIXED SETUP`. The weapon/style labels identify the
  starting setup and indicate changes. Expected intervals show a range when
  necessary; Defence changes show the initial and final values. This permits
  weapon-switch tests without pretending they were a single fixed setup.
- All seven skill XP values are compared independently with their starting
  values. The report shows signed total XP delta and the number of changed
  skills. Even offsetting changes produce `XP CHANGED`. This is a check, not an
  XP grant or rollback; manual skill edits during a run will also be detected.

Results occupy ten chat lines, including header/footer. The existing dummy
guards remain responsible for denying health loss, rewards and combat XP. The
test tool neither weakens those guards nor suppresses XP on ordinary creatures.

## Lifecycle and limits

Sessions are owned by the player object and retain only the target GUID, never
a creature pointer or background timer/callback. Logout, map removal/transfer,
death, dummy disappearance, switching attacks to another target, permission
removal, and shutdown cancel safely without a report. Death/target/permission
cancellations send a brief acknowledgement when possible. Ordinary combat on a
new target is not stopped by cancellation of the old dummy test.

Session timestamps are temporary memory, discarded after report/cancellation.
No files, database rows or server-data exports are written. A 50,000-sample
safety limit ends an unusually dense run early with `SAMPLE LIMIT`.

## Quick live acceptance

1. Equip a known Stage 1F weapon, choose `.rs accurate`, select a dummy, and run
   `.rs attacktest 1`. Confirm attacks start automatically, `status` counts down,
   and the ten-line COMPLETE report arrives with attacks stopped and all seven
   XP values unchanged.
2. Start another run. Walk out of range/face away for several seconds, return,
   then use `stop`. Expect STOPPED, measured pause time, and no invented swings.
3. Start a run and use `cancel`: only an acknowledgement, with no report. Check
   that a second start during an active run is refused and 0/31/decimal durations
   are refused.
4. During a run, swap weapons or change selected dummy Defence. Expect MIXED
   SETUP and measured intervals, not an artificial reset to the expected rate.
5. Remove the dummy during a run or log out. Expect cancellation and no stale
   report after the dummy is gone or after logging back in.

Live command/lifecycle acceptance remains for the user's in-game confirmation.

## Automated validation

The focused combat suite is built by `build/warscape-check/run.cmd`. The full
native test executable is built with CMake `BUILD_TESTING=ON`. It needs the
installed server's runtime DLL directory on the process search path:

```powershell
Set-Location C:\WoWDev\TrinityCore\build\bin\Release
$env:PATH = 'C:\WoWDev\TrinityServer;' + $env:PATH
.\tests.exe
```

Run the compiled executable if CTest discovery reports an empty test list; an
empty CTest run does not verify anything. These tests use synthetic data and do
not start servers, connect to the live databases, or grant player XP.
